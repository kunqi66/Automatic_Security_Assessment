# demo/ —— 第一个靶场，已不是演示入口

**要跑演示请用 [`ranges/`](../ranges/)，不要用这里。**

`vulnerable-demo-app/` 是本项目**最早**的那个靶场（2026-10-16 当天写的）。
它现在被 `ranges/ecommerce` 完全覆盖：后者 323 行 / 4 个文件 / 11 条钉死的
GROUND_TRUTH 条目，而这里只有 132 行 / 1 个文件 / 6 个路由。

## 那为什么还留着

两条测试的 docstring 用它作为**实测来源**，而且是**只有它**能当这个来源：

- `backend/tests/test_analysis_language_gate.py` —— 「Python 项目被判成不支持 Python，
  一行都没扫，报告输出 0 个漏洞」
- `backend/tests/test_poc_verify_id_seam.py` —— 「探针真跑了，但回来全是 `id=0`，
  7 条漏洞全 `unverified`，而阶段状态是 `completed`」

这两条写的都是「实测（2026-10-16，靶场 vulnerable-demo-app）：……」。**本仓库不是
git 仓库**，删掉这个目录就没有任何地方能再取出这份证据 —— 那两句话会从
「可复核的实测」退化成「不可证伪的断言」。

本项目的第一标准是**真实度和可复现性**，所以留一个 4.7KB 的文件换两处实测
可被复核，是划算的。**它不是产品代码，不被 `app/` 引用，也不参与任何测试。**

## 它还有一处独有价值（已上移）

`vulnerable-demo-app/app.py` 的模块注释原本是**唯一**写清楚「靶场入口必须是
根目录的 `app.py`、端口必须是 5000」的地方 —— 这条约束违反了不会报错、
只会让沙箱超时。这段说明已上移到
[`ranges/README.md` § 写一个新靶场的硬约束](../ranges/README.md#写一个新靶场的硬约束)，
因为那是靶场作者真正会看的地方，而这里原先只有写第一个靶场的人知道。
