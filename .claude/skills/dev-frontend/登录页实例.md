## 3. 对账：原型与设计对不上的地方 ⚠️

这是本页最关键的一节。原型里有 **3 个元素 + 1 个陷阱**在设计里没有对应。

### 冲突 ① 图形验证码 —— 原型有，**接口不存在**

| | |
|---|---|
| 原型 | `Field/验证码`(`XnPP9`)：输入框 + 124×42 的验证码图，画着 `7K3M` |
| 设计 | fe-01 §3 把 `GET /api/auth/captcha` 标为 **❌ 未定义**；§10 登记为字典 §9 **#31**（PRD §4.2 要求、§8.1 无接口、§7.2 无存储位） |
| **处置** | **整个 `Field/验证码` 不生成**。fe-01 §10 明确：「验证码一栏应先注释掉**而非留空输入框**」——留一个永远校验不过的框比暂时没有更糟。前端校验规则同步少一条。 |

### 冲突 ② 忘记密码？ —— 原型有，**设计明确不做**

| | |
|---|---|
| 原型 | `Forget`(`CeQUF`)：「忘记密码？」$brand 12.5 |
| 设计 | fe-01 §1.2 明确不做：「不做注册、找回密码、修改密码」。PRD 也未定义该入口 |
| **处置** | **不生成**。`Options` 行只保留「记住我」（若冲突 ③ 决定要的话）。 |
| 附带 | 画原型时为了版式平衡放了它，属于 `pencil-draw` §第 5 步「让评审者一眼看到业务约束」的产物——**原型里出现 ≠ 需求里有**。 |

### 冲突 ③ 记住我（7 天内免登录） —— 原型有，**勾选框没有对应行为**

| | |
|---|---|
| 原型 | `RememberRow`：勾选框 + 「记住我（7 天内免登录）」 |
| 设计 | fe-01 §4.4 已定：refresh 一律存 `localStorage`，没有「不记住」的分支 |
| **处置** | 二选一，**不要擅自实现**：① 不做该勾选框（refresh 始终持久化，与 §4.4 一致）；② 要做，则必须先定义「不勾选时 refresh 存 `sessionStorage`」——那是**新增需求**，进 spec §9 待确认 + 字典 §9。 |

### 陷阱：原型展示的是**填好状态**，不是空状态

`Field/用户名` 的 Input 里写着 `chenjing`，密码框是 `••••••••`。
这些是**示意用的假数据**，不是 placeholder，更不是默认值。

- 真实输入框应为**空**，靠 `placeholder` 提示（`el-input` 的 `placeholder`）。
- 密码框的 `letterSpacing:2` 是原型为了画出 `••••••••` 的圆点间距而加的，
  **不要**照抄到真实密码输入框上。

## 6. spec 该怎么填（第 4 步的产物）

落到 `vibecoding_doc/specs/P1-0N-fe-login.md`，字段来源：

| spec 字段 | 抄自 |
|---|---|
| §2 数据流 | fe-01 §4.1（store）+ §4.3（401 单飞刷新） |
| §3 组件树与布局 | 本文 §2 的原型结构 + fe-01 §2/§4.2 |
| §4 交互与状态 | fe-01 §4.3 的 4 条流程 |
| §5 接口映射 | fe-01 §3（4 个 ✅ + 1 个 ❌） |
| §6 权限 | 本页无按钮权限；但 `directives/permission.ts` 在此首次定义 |
| §7 安全 | fe-01 §7 全表 |
| §9 待确认 | fe-01 §10 四条 **+ 本文 §3 的三处冲突** |

**§9 至少要写进这四条冲突**（否则评审看不到风险）：

1. 验证码：原型有、接口无 → 已按 fe-01 指示不生成
2. 忘记密码：原型有、设计明确不做 → 不生成
3. 记住我：原型有、§4.4 无对应分支 → **待拍板**（做/不做）
4. refresh 是否改 httpOnly cookie（fe-01 §10 #2）→ **待拍板**
