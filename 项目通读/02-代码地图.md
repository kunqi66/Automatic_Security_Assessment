# 02 · 代码地图

## 一、这个项目怎么分层（先看这个，不然会迷路）

代码里有一张表，写在 `backend/app/__init__.py:5-10`，**原文照抄**：

```text
| 层 | 内容 | 允许依赖 |
| L1 接口层     | api/                                     | L2、L3、L4 |
| L2 编排层     | orchestrator/、agents/                   | L3、L4     |
| L3 领域引擎层 | analysis/、verify/、chain/、sandbox/、report/、projects/ | L4 |
| L4 基础设施层 | core/、db/、llm/、models/、schemas/      | 无         |
```

**只能从上往下依赖，不能反向。** 两条硬约束会被反复提到：

- `analysis/` **不许** import `db/`（引擎要能脱离数据库单测）
- 领域引擎层**不许** import FastAPI（`verify/`、`analysis/` 里出现 `from fastapi import ...` 就是错的）

> ⚠️ **这里有个大坑，面试极易被绕进去**：项目里的 **`L1–L4` 有三套完全不同的含义**：
>
> | 写法 | 出处 | 指什么 |
> |---|---|---|
> | **L1 接口层 / L2 编排层 / L3 领域引擎层 / L4 基础设施层** | `app/__init__.py:5-10` | **架构分层**（上面这张表） |
> | **L1 不参与判定 / L2 不引入事实 / L3 输出必校验 / L4 可降级不阻断** | `概要设计总纲.md:619-632` | **LLM 可控性四铁律** |
> | **L1 可忽略 / L2 可降级 / L3 可跳过 / L4 可重试 / L5 致命** | `概要设计总纲.md:636-674` | **错误分级** |
>
> **三套都真实存在于代码和文档里。** 被问「你说的 L1 是什么」时，
> 第一反应应该是反问/说明是哪一套 —— 答混了会被认为没读透自己的代码。

## 三、每块干什么（一句话 + 入口文件）

### L1 接口层 · `backend/app/api/`

**只做三件事**：校验参数、检查权限、转交给引擎。**不许写业务逻辑，不许写 SQL。**

| 文件 | 接口数 | 管什么 |
|---|---|---|
| `auth.py` | 2 | 登录 / 查"我是谁" |
| `projects.py` | 6 | 项目建档、上传源码包、删除 |
| `assessments.py` | 7 | 新建/停止/恢复评估、查阶段、**SSE 日志流** |
| `vulnerabilities.py` | 5 | 漏洞列表/详情、人工复核、生成补丁、采纳补丁 |
| `reports.py` | 4 | 报告列表/预览/导出/下载 |
| `admin.py` | 4 | LLM 参数、沙箱配置 |
| `audit.py` | 1 | 审计日志（**只读**） |
| `chains.py` / `dashboard.py` / `health.py` | 各 1 | 攻击链 / 大盘统计 / 健康检查 |

**入口**：`app/main.py`。**权限总闸**：`app/api/deps.py`（第 60–87 行是角色→权限表）。

> ⚠️ `deps.py:141` 有个 `get_optional_user` 定义了但**没有任何调用点** ——
> 别以为 SSE 走的是它（SSE 实际用标准 Bearer 头 + 强制鉴权）。这是一处死代码。

### L2 编排层 · `orchestrator/` + `agents/`

- **`orchestrator/engine.py`** —— 五阶段的主循环。**这是整个系统的"心跳"**。
- **`orchestrator/queue.py`** —— Redis Stream 收发 + 失败重试（不用 Celery，见 [01-这是什么.md](01-这是什么.md) §五）。
- **`orchestrator/cancel.py`** —— 协作式取消（不切断事务）。
- **`agents/`** —— 五个阶段各一个类，`base.py` 是它们的共同父类。

**五个 Agent 与它们的容错级别**（`agents/base.py` 声明）：

| 阶段 | 文件 | 行数 | 失败后果 |
|---|---|---|---|
| `recon` 侦察 | `recon.py` | 545 | **致命** → 整个评估 failed |
| `code_audit` 静态审计 | `code_audit.py` | 330 | **致命** → 整个评估 failed |
| `poc_verify` 动态验证 | `poc_verify.py` | 482 | 可跳过 → 标 `skipped`，继续 |
| `exploit_chain` 攻击链 | `exploit_chain.py` | 311 | 可跳过 → 标 `skipped`，继续 |
| `report_gen` 报告 | `report_gen.py` | 210 | **致命** → 整个评估 failed |

> 为什么 `base.py` 把容错级别写成**类上的声明**而不是 `engine.py` 里的 `if stage in (...)`？
> 原文（`agents/base.py:14-19`）：「把那张表写成 `engine.py` 里的 `if stage in (...)`，
> 就又回到『**引擎里散落阶段名**』了。」

### L3 领域引擎层 —— 项目的主体

#### `analysis/` 静态污点引擎（5,574 行，最厚）

自己写的 SAST。**按数据流走，不是按关键字匹配**：

| 文件 | 干什么 |
|---|---|
| `parser.py` | tree-sitter 解析源码成语法树（**不用 Python 内置 ast**，见下） |
| `sources.py` | **41 条**"脏数据从哪来"的规则（`request.args` 等） |
| `sinks.py` | **35 条**"危险函数"的规则（`execute`、`eval` 等） |
| `sanitizers.py` | **16 条**"净化函数"的规则（`escape`、`quote` 等） |
| `propagators.py` | **34 条**"数据会继续流"的规则（赋值、拼接等） |
| `taint.py` | **污点传播算法本体** —— 从 source 出发，一步步走到 sink |
| `__init__.py` | 对外入口 `analyze()` + **11 条已知精度边界表**（第 36–52 行） |

**从哪读起**：`__init__.py` 的 11 条边界表 → `taint.py`（核心算法）→ `sinks.py`（看规则长什么样）。

#### `verify/` 动态验证 + 补丁校验（5,226 行）

| 文件 | 干什么 |
|---|---|
| `probe.py` | 构造**无害探针**（带 nonce 随机串），映射漏洞类型 → 探针模板 |
| `runner.py` | 在容器里跑靶场、发探针、看响应里有没有 nonce |
| `patch_guard.py` | **749 行，补丁的四道校验全在这**（详见 [04-代码精读.md](04-代码精读.md)） |

#### `chain/` 攻击链推演（1,525 行）

规则引擎，把已确认的漏洞按"权限跃迁逻辑"串成 DAG。
**最后一环是推演（`inferred`）不是实测（`verified`）** —— 这是无害化红线。

#### `report/` 报告汇编（3,034 行 + 模板 1,069 行）

| 文件 | 干什么 |
|---|---|
| `scoring.py` | **374 行纯函数**：算安全分、等级、第 3 章顺序、**第 5 章整改顺序** |
| `assembler.py` | 782 行，把数据库里的散件拼成一份报告 |
| `render.py` | Jinja2 渲染 HTML / Markdown |
| `pdf.py` | Playwright 把 HTML 打成 PDF（**惰性**，只在导出时做） |
| `templates/` | 13 个 `.j2` 模板 + 1 个 CSS，共 1,069 行 |

#### `sandbox/` 容器生命周期（813 行）

经 SSH 连远端 ECS 的 Docker，起一个 `network_disabled=True` 的容器，
只读挂载源码，跑命令，然后销毁。

#### `projects/` 源码接入（1,816 行）

Git clone 或解压上传包 → 校验路径穿越（`safe_join`，`workspace.py:150-174`）→
建工作区。**绝对路径换算只允许出现在这里和 `sandbox/`**（模块间契约）。

### L4 基础设施层

- **`llm/`（2,062 行）** —— 四个表达点 + 降级模板 + 实体白名单校验。
  **`llm/fallback.py` 是「拿掉 LLM 结论不变」这句话的实际载体**。
- **`models/`（840 行）** —— 15 张表的 ORM 定义。
- **`core/`（749 行）** —— `config.py`（配置）、`exceptions.py`（异常）、
  `security.py`（bcrypt + JWT）、`response.py`（错误响应渲染）。
- **`db/`（319 行）** —— 会话管理 + 审计日志。

## 四、前端地图 · `frontend/src/`（7,157 行）

**5 个页面**（`pages/`）：`Dashboard`、`Login`、`Workbench`、`ReportCenter`、`SandboxConfig`。

**模块**（`modules/`，按业务分）：

| 模块 | 对应需求里的哪个模块 | 关键文件 |
|---|---|---|
| `dashboard/` | 概览大盘模块 | ECharts 统计图 + 新建任务表单 |
| `workbench/` | 流水线监控模块 | 五阶段步进器 + SSE 日志窗 |
| `vuln/` | 漏洞视窗模块 | Monaco Diff 看补丁、源码高亮、污点步进 |
| `topology/` | 拓扑图谱模块 | React Flow + dagre 排版的攻击链 |
| `report/` | 报告导出模块 | 预览 + 导出按钮 |

**基础设施**：

- `api/client.ts` —— axios 实例，**401 时清 token 跳登录页**（拦截器在 React 树外，拿不到 router）。
- `api/useLogStream.ts` —— **SSE 客户端**。用 `fetch` + `ReadableStream` 手写解析，
  **刻意不用 `EventSource`** —— 因为它不能设请求头，只能把 JWT 塞进 URL 查询串，
  而查询串会进 nginx access log / 浏览器历史 / Referer，**等于泄露凭证**。
  断线重连靠 `Last-Event-ID`，指数退避最多 10 次。
- `store/` —— 2 个 zustand store。`vulnSelection.ts` 是**漏洞表格与拓扑图之间的唯一契约**
  （靠 store 通信，**不互相 import 组件**）。

## 五、`ranges/` 为什么单独占一节

**因为它是"量具"，不是"示例代码"。**

```
ranges/ecommerce/GROUND_TRUTH.yaml      ← 每个漏洞钉死 文件 + 行号
ranges/usercenter/GROUND_TRUTH.yaml
```

`benchmark.py` 拿系统的扫描结果去对这份"标准答案"，误差窗口 **±2 行**（`LINE_WINDOW = 2`）。

> 🔴 **由此产生一条铁律：不要为了"让漏洞更明显"去改 `ranges/` 的源码。**
> 改一行，`GROUND_TRUTH` 里钉的行号就全错位，召回率会**静默暴跌**（不报错，只是数字变难看）。
>
> 这不是假设，是踩过的坑 —— 详见 [06-知识点精讲.md](06-知识点精讲.md) 卡片 11。
