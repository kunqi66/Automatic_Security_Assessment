## 30 秒版

给一个源码工程（Git 地址或压缩包），系统自己跑完五步 ——
**侦察 → 静态污点扫描 → 在隔离容器里发无害探针验证 → 拼攻击链 → 出报告** ——
最后交出一份带**可复现证据**的安全评估报告。

关键不是"用了大模型"，而是**把大模型关在表达层**：
漏洞有没有、几级、什么状态、攻击链怎么连、整改谁先谁后，
**全部由确定性代码算出来**；大模型只负责把这些结论"说成人话"。

## 5 分钟版

### 它到底解决什么问题

传统 SAST（静态扫描）的毛病是**报一堆、真假难辨**，人得逐条去核。
这个项目在静态扫描后面接了一步**动态验证**：
把源码只读挂载进一个**断网的容器**，在容器里把靶场起起来，
对着可疑端点发一条**无害探针**，看响应里有没有回显出它埋进去的随机串（nonce）。

- 回显了 → `verified`（**逐点确认**：就是你看到的这一行被跑通了）
- 没回显，但风险模式还在 → `potential`（**仅类别级**：这类问题在本目标上确实存在，但没证明是你那一行）
- 被动态证伪 → `rejected`

这套四态在报告里是**分开措辞**的，不会把"类别级"说成"你这行有问题"。

### 一次评估实际会经过什么

```
用户点「新建评估」
  └─ API 校验权限 → 建 assessment 行（status=created）→ 投递到 Redis Stream
       └─ worker 消费（并发恒为 1）
            ├─ 1. recon        识别语言/入口/依赖        ← 失败 = 整个评估 failed
            ├─ 2. code_audit   tree-sitter 污点分析      ← 失败 = 整个评估 failed
            ├─ 3. poc_verify   容器内发无害探针          ← 失败 = 只标 skipped，继续
            ├─ 4. exploit_chain 规则引擎串攻击链         ← 失败 = 只标 skipped，继续
            └─ 5. report_gen   从数据库快照汇编报告      ← 失败 = 整个评估 failed
       └─ 全程往 Redis Stream 写日志 → SSE 推给前端
```

**第 3、4 步失败为什么还能继续**：验不了不等于没问题。
因为沙箱连不上就不出报告，等于把"基础设施故障"变成了"这个项目很安全"——
那是最糟的一种错。

## 面试里最值得讲的三件事（直接点名，别自己总结）

### ① 把大模型关进笼子 —— 而且是"可验证"的那种关法

不是"我用了 LLM 做安全分析"，而是
**"我设计了一套让 LLM 无法污染结论的架构，并且有办法证明它做到了"**。
证据是四层铁律（[05-开发原理.md](05-开发原理.md)）+ 一个能当测试用的判据：
**拿掉 LLM，系统的结论必须一字不变，只有措辞会变**。

### ② 自研污点引擎的**误报控制**（不是"我能扫出漏洞"）

会写扫描器的人很多，**能说清"我为什么在这一版选择漏报而不是误报"的人很少**。
这个项目的引擎有一条结构性保证：**必须一个"脏"的实参真的到达危险函数才产出漏洞**，
光看见危险函数不算（`taint.py:657-663`）。
另外它把 **10 条已知精度边界逐条登记、并标注偏向"报多"还是"漏"** ——
理由是安全工具里这两种代价**不对称**。

### ③ 无害化红线：**可以推断能打穿，绝不自己打穿**

攻击链的最后一环（上传 WebShell → 宿主机 RCE）是**推演出来的，不是打出来的**，
在数据结构里用 `verified` / `inferred` 两态**显式区分**，报告里也写明
"第 1–2 环已无害验证，第 3 环由已证实的前置条件推演得出，未实际执行"。
设计文档里明确否决了"真的执行 RCE"这个方案（`概要设计总纲.md:760`）。

> 这条在面试里是**加分项**：它证明你知道安全工具的边界在哪。
> 扫描器可以推断"这里能打穿" —— 但绝不应该自己打穿。

## 诚实交代：哪些核实过、哪些没有

**逐条核实过（打开代码看过行号）**：本项目所有 `文件:行号` 引用，
以及上表里的代码行数、规则条数、benchmark 数字（亲自跑）。

**跑起来验证过的**：
- 后端 775 passed / 3 skipped（`pytest`，collect 778 —— 差额来自 `parametrize`）
- benchmark 实跑：ecommerce 11/11、usercenter 3/5、合计 **14/16**、误报 **0**
- 前端 4 个页面无白屏、无控制台异常、报告中心能打开真实报告正文
  （`frontend/scripts/smoke.mjs`，用 CDP 驱动无头浏览器）
- 三种格式报告真的能下载下来（PDF 578,030 字节，Markdown 22,884 字节）

> ⚠️ **`benchmark.py --dynamic` 不是"能用但退出码 2"** —— 它是**刻意未实现**
> （`backend/tests/benchmark.py:238-262` 打印一句说明然后 `return 2`）。
> 原因是动态验证要 `Sandbox` + `WorkspaceHandle`，而 workspace 绑在数据库的项目实体上，
> 引 DB 会毁掉这个脚本「不依赖任何外部环境」的立身之本。
> **所以"动态剔除误报"的效果在本项目里没有实测数字。**
> （本条曾被我写错成"退出码 2 表示有 finding 没被验证" —— 以代码为准。）

**没核实 / 做不到的，明说**：
- **DeepSeek 的 key 没配**，所以报告里全部是模板降级产物。
  这**不影响结论**（这正是 L1 的设计），但意味着"LLM 生成补丁"这条路
  在这台机器上**没有端到端跑通过**。
- `resource_metrics` 表**恒为空** —— 采样器写好了但**没有任何地方调用它**。
  详见 [06-知识点精讲.md](06-知识点精讲.md) 卡片 12 与
  `backend/docs/资源采样为什么是空的.md`。
- 靶场的**动态验证**（`--dynamic`）本次没跑（需要沙箱可用），
  所以"动态剔除误报"这一步的效果**没有实测数字**。
