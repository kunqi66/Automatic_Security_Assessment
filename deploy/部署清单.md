# 启动清单 —— 代码跑本机，中间件用服务器

> **拓扑（这一版的核心）**：代码**不部署**，就跑在这台 Windows 上。
> 服务器只提供三个中间件：MySQL、Redis、Docker。
>
> ```
>   ┌──────────────── 本机 Windows ────────────────┐      ┌────── ECS 60.205.138.167 ──────┐
>   │                                              │      │                                │
>   │  uvicorn app.main:app   :8010  ← 前端连这个   │      │                                │
>   │  python -m app.worker                        │      │                                │
>   │         │                                    │      │                                │
>   │         ├── MySQL  ──── SSH 隧道 ────────────┼─────▶│ 3306  (asa_user)               │
>   │         ├── Redis  ──── SSH 隧道 ────────────┼─────▶│ 6379  db=3                     │
>   │         └── Docker ──── ssh:// 直连 ─────────┼─────▶│ docker.sock → 探针容器          │
>   │                                              │      │                                │
>   │  源码工作区 D:/.../workspaces                 │      │  /srv/asa/tasks/{id}/src       │
>   └──────────────────────────────────────────────┘      └────────────────────────────────┘
> ```
>
> ⚠️ **两种连接用的认证方式不一样**，这是最容易卡住的地方：
> MySQL / Redis 走**密码**（隧道脚本用 paramiko），
> Docker 与源码同步走**密钥**（它们 shell out 到系统 `ssh`，非交互、不可能输密码）。
> 见下面第二节 ②。

---

## 一、安全组：一个新端口都不用开

API 绑本机 `127.0.0.1:8010`，是**你机器上的本地端口**，与安全组无关。
服务器侧需要的只有 `22`（SSH）—— 你本来就在用。

所以：**不用去阿里云控制台动任何规则。**

**顺带说一件事**（不是本项目要你做的，只是实测结果）：我从本机逐个测了
ECS 的 TCP 可达性，结论和「容器监听了什么」不一样：

| 端口 | 服务 | 公网可达 |
|---|---|---|
| 22 | SSH | ✅ 正常 |
| 3306 | MySQL | ❌ 超时（安全组挡着，隧道因此是**必需**的） |
| 6379 | Redis | ❌ 超时（同上） |
| **19530** | Milvus | ✅ **可达** |
| **8000** | 未知服务 | ✅ **可达** |

也就是说，真正暴露在公网上的是 `19530` 和 `8000` 这两个历史遗留服务。
如果你想收窄，值得看的是它们 —— 但按你「先不动这台机器」的要求，我**只报告不动手**。

## 二、需要你做的 5 件事

### ① 建 MySQL 库与专用账号 ⚠️ **当前不存在**

**实测（2026-10-16）**：用 `backend/.env` 里配的 `asa_user` 连 ECS MySQL 8，
返回 `ERROR 1045 Access denied` —— 账号还没建。

在 ECS 上执行（`<密码>` 换成你自己生成的强口令）：

```sql
CREATE DATABASE IF NOT EXISTS security_assessment
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

CREATE USER IF NOT EXISTS 'asa_user'@'127.0.0.1' IDENTIFIED BY '<密码>';
GRANT ALL PRIVILEGES ON security_assessment.* TO 'asa_user'@'127.0.0.1';
FLUSH PRIVILEGES;
```

> **为什么 host 是 `127.0.0.1` 而不是 `%`，明明我是从本机连的？**
> 因为隧道**在 ECS 那一端**才落地：paramiko 从 ECS 本机去连 `127.0.0.1:3306`，
> 所以 MySQL 看到的来源就是 `127.0.0.1`。用 `%` 等于额外允许任何人从公网
> 直连你那个对 `0.0.0.0` 开放的 3306 —— 而这个方案根本不需要。

### ② 🔴 把本机公钥授权到 ECS —— **当前是通的唯一硬阻塞**

**实测**：`ssh -o BatchMode=yes root@60.205.138.167` 返回
`Permission denied (publickey,password)`。本机 `~/.ssh/id_rsa` 存在，
但**没有装到服务器上**；`~/.ssh/config` 里那个 host 条目也没写 `IdentityFile`
（所以走的是默认 `id_rsa`，没问题，只是没被授权）。

**为什么这条是硬阻塞**：`poc_verify` 阶段要起容器，走
`DOCKER_HOST=ssh://root@60.205.138.167`；而 docker-py 的 ssh 传输
（`use_ssh_client=True`）是 spawn 一个系统 `ssh` 进程。系统 `ssh` 在非交互
场景下**没有任何办法输密码** —— 它只会失败。源码同步（`app/projects/sync.py`）
同理，它显式带了 `-o BatchMode=yes`，就是为了「绝不挂在那儿等口令」。

本机执行（会提示输一次服务器密码）：

```bash
ssh-copy-id -i ~/.ssh/id_rsa.pub root@60.205.138.167
```

没装 `ssh-copy-id` 的话，等价手工做法：

```bash
# 1) 打印本机公钥，复制整行
cat ~/.ssh/id_rsa.pub

# 2) 登进服务器，粘到 authorized_keys
ssh root@60.205.138.167
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo '<粘贴上面那一整行>' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

验证（**必须免密成功**，出现任何密码提示都说明没装好）：

```bash
ssh -o BatchMode=yes root@60.205.138.167 'echo KEY_OK'
# 期望输出：KEY_OK
```

> ⚠️ 这一步**我不代做**。往你服务器上装长期有效的登录凭据属于「持久化访问」，
> 之前一次类似的尝试被权限分类器拦下过，我没有绕过 —— 这类动作由你自己确认更合适。

### ③ 生成 `JWT_SECRET`

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

### ④ 填 `backend/.env`

本机这份 `.env` **已经配好了大半**（隧道端口、docker host、工作区路径都对），
只差下面这几个空值：

| 变量 | 填什么 | 不填的后果 |
|---|---|---|
| `MYSQL_PASSWORD` | ①里设的密码 | **启动即失败**（迁移连不上库） |
| `JWT_SECRET` | ③生成的串 | 本地 `DEBUG=true` 下无所谓，但填上省事 |
| `REDIS_PASSWORD` | 见 ⑤ | 连不上 Redis，worker 起不来 |
| `DEEPSEEK_API_KEY` | 你的密钥 | **不填完全可用** —— 文案降级为确定性模板，**结论一字不变**，只是措辞朴素 |

**已经是对的、不用动**：

```
DEBUG=true                     # 本地开发。注意：生产自检只在 DEBUG=false 时生效
MYSQL_HOST=127.0.0.1
MYSQL_PORT=13306               # ← 隧道本地端口，不是 3306
MYSQL_USER=asa_user
MYSQL_DATABASE=security_assessment
REDIS_HOST=127.0.0.1
REDIS_PORT=16379               # ← 隧道本地端口
REDIS_DB=3
DOCKER_HOST=ssh://root@60.205.138.167
ECS_SOURCE_ROOT=/srv/asa/tasks
WORKSPACE_ROOT=D:/myself_complete_code/.asa/workspaces
REPORT_ROOT=D:/myself_complete_code/.asa/reports
```

> `DEBUG=true` 时**不需要** `GIT_URL_ALLOWLIST`（生产自检不跑）。
> 哪天你要把它跑在公网上，那时才需要，且**必须是 JSON 数组**：
> `GIT_URL_ALLOWLIST=["https://gitee.com/你的账号/"]` —— 逗号分隔会在
> import 期就抛 `SettingsError`。

### ⑤ Redis 认证：填一下就行，不是安全问题

**实测**：ECS 的 Redis 是 Docker 里的 `redis:7.2`。

**它没有被公网暴露** —— 我从本机实测过 `60.205.138.167:6379`，**超时**，
安全组挡着（容器里虽然监听 `0.0.0.0`，但外面进不来）。
所以这里**不是**一个安全议题，只是「`.env` 里得填对」：

- **Redis 设了密码** → 把口令填进 `REDIS_PASSWORD`。
- **没设** → `REDIS_PASSWORD=` 留空即可。

我**没有去读它的 `requirepass`**（那会把口令打印进对话），所以不知道设没设 ——
你 `ssh` 上去 `redis-cli CONFIG GET requirepass` 一眼就知道。

本项目**只用 `db=3`**，不碰你的 `db=0`，不改任何现有 key。

## 三、在本机跑起来（3 步）

### 第 1 步：开隧道（**常驻，单开一个终端**）

MySQL 与 Redis 不对本机开放，靠 SSH 隧道。本机的 `13306 → ECS 3306`、
`16379 → ECS 6379`，正好对上 `.env` 里的端口。

```bash
cd D:/myself_complete_code/agent/Automatic_Security_Assessment
uv run --with paramiko python -u deploy/tunnel.py
```

> ⚠️ **已知坑**：SSH 会话断掉后，本地监听端口**不会消失**。症状是
> 「TCP 握手成功、但查询挂死」—— 看到就重启隧道，别去查 MySQL。
> 今天已经遇到过一次。

### 第 2 步：建表（一次就够）

```bash
cd D:/myself_complete_code/agent/Automatic_Security_Assessment/backend
uv run alembic upgrade head
```

会建 15 张表。验证：

```bash
uv run alembic current          # 应显示 3193e02f45bd (head)
```

**顺手再种一行沙箱配置**（同样一次就够）：

```bash
uv run python -m app.scripts.seed_sandbox
```

幂等 —— 已有同名行就原样不动（要覆盖得显式加 `--force`）。

> **不种会怎样？** 评估不会失败：`engine._resolve_sandbox_config` 读不到
> 就回落到 `core/config.py` 的默认值（降级是允许的）。但管理页
> 「沙箱与环境配置」会永远显示「暂无沙箱配置」，管理员**无从下手**，
> 而 `GET /admin/sandbox/configs` 返回空数组也看不出是没配还是坏了。
>
> 种子值是 `cpu_limit=0.5` / `memory_limit_mb=256`，**刻意不等于**表列的默认值
> （`1.0` / `1024`）—— 那是引擎在管理页接通之前实际在用的两个数。取列默认值
> 会让「种这一行」这个动作本身把沙箱内存翻 4 倍，而部署机是 2 vCPU / 7.3G
> **无 swap**，症状会是随机 OOM 而不是报错。

### 第 3 步：起 API 与 worker（**各一个终端**）

```bash
# 终端 A —— 后端 API，前端连 127.0.0.1:8010
cd D:/myself_complete_code/agent/Automatic_Security_Assessment/backend
uv run uvicorn app.main:app --host 127.0.0.1 --port 8010

# 终端 B —— 任务 worker（真正跑五个阶段的是它，不是 API）
cd D:/myself_complete_code/agent/Automatic_Security_Assessment/backend
uv run python -m app.worker
```

> **为什么 API 和 worker 是两个进程**：API 只负责收发请求与写队列，
> 五个阶段的执行全在 worker 里。只起 API 的话接口都能调通、任务永远不动 ——
> 这个症状很容易被误判成「队列坏了」。
>
> 前端另开一个终端：`cd frontend && npm run dev`

## 四、沙箱镜像（在 ECS 上建，一次就够）⚠️ **当前未构建**

**实测**：ECS 上只有 `redis:7.2` / `mysql:8.0` / `milvusdb/milvus:v2.5.10` /
`zilliz/attu` 四个镜像，**没有 `asa/sandbox-base:latest`**。

不构建的后果**不是报错，而是静默降级**：`poc_verify` 阶段标 `skipped`，
所有漏洞停在「潜在」，报告注明「本轮未做动态验证」。
`recon` / `code_audit` / `report_gen` 全都正常。

Dockerfile 在本机 `backend/app/sandbox/base/Dockerfile`，需要先传上去：

```bash
# 本机：传这一个文件就够（它没有 COPY/ADD，构建上下文无所谓）
scp D:/myself_complete_code/agent/Automatic_Security_Assessment/backend/app/sandbox/base/Dockerfile \
    root@60.205.138.167:/tmp/asa-sandbox-base/Dockerfile

# ECS：构建
ssh root@60.205.138.167 "docker build -t asa/sandbox-base:latest /tmp/asa-sandbox-base"
```

> 这个 Dockerfile **没有 `COPY` / `ADD`** —— 它只装依赖（`requests` / `Flask` /
> `SQLAlchemy`）并建一个 `sandbox` 用户，被扫的源码是运行期挂载进去的。
> 所以构建上下文是什么目录都不影响，传单个文件就够。

> 镜像里预装了 `requests` / `Flask` / `SQLAlchemy`。
> **探针容器是 `network_disabled=True` 的，没有出网** —— 运行期 `pip install`
> 必然失败，依赖必须构建期装好。这也是为了可复现：运行期装依赖会让结论与
> 「当时镜像源拉到哪个版本」耦合，同一份源码两次评估可能不一样。
>
> **不需要**建 Docker 网络：容器不出网，被扫应用与探针在同一个容器里，
> 探针请求的是容器内的 `localhost:<port>`。

## 七、已知的、你可能想知道的取舍

- **探针容器的源码路径**：本机的源码工作区在 `D:/...`，而容器跑在 ECS 上，
  挂载不了本机磁盘 —— 所以 `recon` 之后会把源码树打成 tar 流**推送到
  `/srv/asa/tasks/{id}/src`**，容器挂那个目录。这就是「数据面路径空间」
  （契约 5）存在的原因：`workspaces` 是本机的，`/srv/asa/tasks` 是服务器的，
  **两套路径空间不能混**。
- **PDF 是「惰性」的**：`report_gen` 阶段不生成 PDF，首次导出/下载时才生成。
  在 2 vCPU 上把它塞进报告阶段会挤掉「报告生成 ≤30s」这个指标。
- **DOCX 刻意没做**：设计已冻结为「PDF / HTML / MD 三选」，
  加第四套排版会破坏「一套数据三格式」这条不变量。
- **Redis 用 `db=3` + Stream 而不是 Pub/Sub**：Pub/Sub 是即发即弃的，
  断线那几秒的日志永久消失；Stream 保留历史，前端回传 `Last-Event-ID` 就能补读。
- **并发固定为 1**：2 vCPU 上并行评估只会互相拖慢，而且会让「同一份源码两次
  结论不同」变得难以复现。
- **服务不是常驻的**：隧道 + API + worker 都是前台进程，关掉就停。
  本地开发够用；要开机自启再另说。
