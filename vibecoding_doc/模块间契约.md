## 契约 1：B5 → B2（沙箱调用）

**归属**：`app/sandbox/ports.py`（由 B2 拥有），B5 只 import 这里的类型。

**为什么用 `Protocol` 而不是直接 import `SandboxService`**：B5 只需要「跑一个容器、
拿回结果」这一件事。让它依赖完整的沙箱服务，意味着 B2 换实现（比如从 Docker SDK
换成 containerd）会牵动 B5 一起改。**依赖倒置在这里不是洁癖，是因为这两个模块
的开发节奏天然不同** —— B2 要调 Docker API，B5 只管协议。

```python
# app/sandbox/ports.py
@dataclass(frozen=True, slots=True)
class ExecResult:
    exit_code: int          # 超时或被信号杀死时为负数
    stdout: str
    stderr: str
    duration_ms: int
    timed_out: bool

@dataclass(frozen=True, slots=True)
class ContainerSpec:
    image: str
    command: list[str]
    source_mount: str       # **宿主侧**绝对路径，只读挂载
    workdir: str            # 容器内工作目录
    env: dict[str, str]
    cpu_limit: float        # 核数，如 1.0
    memory_limit_mb: int
    timeout_seconds: int
    network_disabled: bool = True   # 默认无出网
    read_only_root: bool = True

class Sandbox(Protocol):
    async def run_once(self, spec: ContainerSpec) -> ExecResult: ...
    async def stats(self, container_id: str) -> tuple[float, float]: ...  # (cpu%, 内存MB)
```

**`run_once` 的语义**：建容器 → 启动 → 等结束（到 `timeout_seconds` 强杀）→
收集 stdout/stderr/退出码 → **无论成败都删除容器**。调用方不需要自己清理。

**约束**：B2 的 `SandboxService` 必须**结构化地**满足这个 `Protocol`（不需要显式继承，
但要能被 `isinstance` 之外的方式对上：方法名、参数名、返回类型一致）。

## 契约 2：B4 → B5 / B3（污点分析结果）

**归属**：`app/analysis/types.py`（由 B4 拥有）。

**字段名一律照抄 `app/models/vulnerability.py` 的列名（PRD §6 命名 SSOT）**，
不做二次改名 —— 「DTO 叫 vuln_type、列叫 type」这种映射是纯翻译税，
而且是字段错位最容易藏身的地方。

```python
# app/analysis/types.py
@dataclass(frozen=True, slots=True)
class TaintStep:
    """污点路径上的一跳。前端 F3 的时间轴直接按这个数组渲染。"""
    step_index: int
    file_path: str      # 相对工作区根的 POSIX 路径
    line: int
    column: int
    symbol: str
    step_kind: str      # source | propagate | sanitize | sink
    snippet: str        # 该行的源码片段，供前端高亮

@dataclass(frozen=True, slots=True)
class Finding:
    rule_id: str
    vuln_type: VulnType
    severity: Severity
    file_path: str
    line_start: int
    line_end: int
    symbol: str
    cwe_id: str | None
    cvss_vector: str
    cvss_score: float
    confidence: float           # 0.0–1.0，**由确定性规则算出，不是 LLM 给的**
    source_kind: str
    sink_kind: str
    guard_blocked: bool         # 路径上存在生效的净化函数
    taint_path: tuple[TaintStep, ...]

@dataclass(frozen=True, slots=True)
class AnalysisResult:
    findings: tuple[Finding, ...]
    files_scanned: int
    total_loc: int
    duration_ms: int
    truncated: bool             # 触发 max_files / max_seconds 上限
```

**铁律 L1 的落点**：`severity` / `cvss_score` / `confidence` / `guard_blocked`
**全部由确定性规则算出**。LLM 在这个模块里**没有任何位置** —— `app/analysis/`
不 import `app/llm/`，也不 import `app/db/`、`fastapi`。

## 契约 3：LLM 层的四个封闭使用点

**归属**：`app/llm/`。

LLM **只出现在表达层**，一共四个点，多一个都不许加：

| # | 用途 | 输入 | 输出 | 降级 |
|---|---|---|---|---|
| ① | 漏洞描述 | Finding（含污点路径） | 一段中文描述 | 模板拼接 |
| ② | Diff 补丁 | Finding + 源码片段 | unified diff 字符串 | 无补丁（patch=null） |
| ③ | 攻击链叙事 | 链的节点与边 | 一段中文叙述 | 模板拼接 |
| ④ | 整改建议 | Finding | 若干条建议文本 | 模板拼接 |

**判据**：拿掉 LLM，系统的**结论**必须一字不变，只有**措辞**会变。

`llm_model` 字段要能区分 `deepseek-chat` 与 `template`，前端据此标注「模板生成」。

补丁必须过**四道校验**（L3），全在 `app/verify/patch_guard.py` 里，不在 LLM 层：
① 是合法 unified diff ② 只落在 ±20 行窗口内 ③ `git apply --check` 干跑通过
④ **把补丁应用到源码上重跑污点引擎，确认污点路径消失**。

## 契约 4：B3 与其余模块

B3 是**唯一的协调者**。它 import 所有模块，没有任何模块 import 它。

```python
# B3 调用的入口（各自模块提供）
projects.ProjectService      .ensure_ready(project_id) -> WorkspaceHandle
analysis.analyze             (manifest, read_source) -> AnalysisResult
sandbox.SandboxService       .run_once(spec) -> ExecResult
verify.verify_finding        (finding, sandbox, handle) -> VerificationResult
chain.build_chain            (findings) -> ChainDraft
report.build_report          (assessment_id, session) -> ReportDraft
llm.*                        四个表达点，全部可降级
```

**阶段失败的处理**（总纲 §8.2 降级矩阵）：计算类依赖（LLM、沙箱）可降级，
存储类依赖（MySQL）不可降级。LLM 不可用 → 用模板，阶段继续；
沙箱不可达 → `poc_verify` 阶段标 `skipped`，**后续阶段继续跑**（不能因为验不了就不出报告）。
