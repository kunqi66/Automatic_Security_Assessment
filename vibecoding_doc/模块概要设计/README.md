## 依赖速查（摘自 [概要设计总纲 §3.3](../概要设计总纲.md)）

**后端**：B3（编排引擎）是唯一协调者，调用 B1/B2/B4/B5/B6；B5 对 B4 仅是数据依赖；**B4 零依赖**（纯函数库）；**B2 不感知业务**（可替换）。

## 分层规则（摘自 [概要设计总纲 §3.4](../概要设计总纲.md)）

```
L1 接口层     api/v1/*
L2 编排层     orchestrator/, agents/
L3 领域引擎层  analysis/, verify/, chain/, sandbox/, report/
L4 基础设施层  core/, db/, llm/, models/
```

**禁止反向依赖**：L3 不得 import `agents/`，L4 不得 import 任何上层，`analysis/` 连 `db/` 都不 import。

## 🎯 第一性原则：可控多智能体

**项目定位是可控多智能体，设计上尽可能避免大模型天马行空。** 完整论证见 [PRD §7.6](../PRD.md) 与 [概要设计总纲 §8.5](../概要设计总纲.md)。四条铁律：

| 铁律 | 一句话 |
|---|---|
| **L1 不参与判定** | 漏洞有无/类型/严重度/状态/攻击链结构/评分/整改顺序全部由确定性代码产出；LLM 输出**永不进入控制流** |
| **L2 不引入事实** | LLM 不得输出输入中不存在的 file_path / 行号 / CVE / 漏洞编码；结构化字段一律代码填充 |
| **L3 输出必校验** | 描述走实体白名单；叙事走节点集合比对；**补丁走四道校验（含污点引擎复验）** |
| **L4 可降级不阻断** | 无 key / 超时 / 限流 / **校验不过**都不中断；显式标注「模板生成」 |

**判据**：拿掉 LLM，系统的**结论**必须一字不变，只有措辞会变。

**补丁四道校验**（L3 最有价值的一环）：① 合法 unified diff ② 只改触发行 ±20 行窗口内 ③ `git apply --check` 干跑通过 ④ **把打完补丁的源码重跑污点引擎，确认该条污点路径消失** —— 补丁不是「LLM 说修好了」，而是「打上之后污点引擎不再报这一条」。

**LLM 封闭用点（4 个，全在表达层）**：① 漏洞描述 ② Diff 补丁 ③ 攻击链叙事 ④ 整改建议文案。**新增用点必须在 PRD §7.6.3 登记，否则不允许引入。**
